# Stage: verification-consent

## 触发条件

`verification-auth` 已确认本地会话的引用验真任务。输入可以是一个普通 `.doc`、`.docx`、`.pdf`，也可以是用户直接粘贴的参考文献列表/单条引用 Markdown 或截图。


## workflow

[VERIFY-0 会话预检] -> [三项影响披露] -> [确认] -> [内部 TODO] -> [下一 Stage]

本 Stage 不执行 `auth status` 或 `login`；认证由前一 Stage 完成。先读取 `../../references/verification-consent-output-example.md`。文档分支的首条可见回复只发送该示例中的披露和确认语，把 `<当前输入文件绝对路径>` 替换为本次输入文件的实际绝对路径；除示例中这一处路径外，不添加执行说明、Agent 自述、TODO、任务卡或结构化确认控件。发送后立即停止，等待用户回复。

确认前不得创建、展示或转述 `VERIFY-1` 至 `VERIFY-5`。收到新的明确确认后，若客户端支持待办列表，才创建或恢复 VERIFY 清单，并且只在客户端内部待办区域维护，不把清单复制到聊天正文；客户端不支持待办列表时，按 Stage 状态继续，不在正文补写清单。

先判断输入分支：

- **文档分支**：严格按引用示例披露三项影响，确认后使用文件识别服务。
- **截图/Markdown 分支**：只处理可见的参考文献列表或单条引用；先展示结构化结果，再取得一次明确确认。确认前不写入正式 JSON，确认前不查询数据库，也不调用文件识别服务。若用户粘贴的是整篇文章、任意正文截图或内容被截断，说明当前只支持参考文献列表/单条引用，并请求更完整输入；不得猜测。

### 文档首条可见回复

逐字遵循 `../../references/verification-consent-output-example.md` 中 `### Example` 下的示例，仅把 `<当前输入文件绝对路径>` 替换为本次输入文件的实际绝对路径。`### Example` 是 Skill 内的说明标题，不输出给用户；从“# 请确认以下信息：”开始发送。首条回复发送后立即停止；不能在同一轮调用 TODO、结构化确认或任何其他工具。

### 截图/Markdown 首条可见回复示例

Agent 自行读取会话中已提供的截图或 Markdown，但只形成预览，不写文件、不调用 CLI。对每条引用展示：

| ID | 原始引用 | 题名 | 作者 | 年份 | DOI | 不确定项 |
|---|---|---|---|---:|---|---|
| ref-1 | 用户提供的完整原文 | 提取的完整题名 | 可确认的作者 | 可确认的年份 | 可确认的 DOI | 无，或明确指出看不清/缺失 |

预览后紧接着用普通用户语言展示三项影响：

- **📄 内容处理**：确认后会整理以上参考文献；该分支不上传文档，也不使用 OCR。
- **🔎 来源查询**：确认后的题名、作者、年份和 DOI 会用于查询 CNKI、Google Scholar、OpenAlex 与 PubMed。
- **💳 计费**：成功完成一次验真，按 `验真服务 × 1` 计费。

最后明确询问：“**✅ 请核对以上整理结果。是否确认内容无误并开始验真？回复‘继续’或指出需要修改的字段。**”发送后立即停止。可见预览和影响披露不得出现 `reference-input/v1`、网关、内部来源路由或计费字段名。信息不完整时只请求补充，不提供“继续执行”的默认分支。

## 行为

1. 文档输入按引用示例发送三项披露；截图/Markdown 输入按对应示例先展示结构化结果、所有不确定项和三项影响。这一步不能调用工具。发送后立即停止，等待新的明确确认。
2. 新确认到达后，若客户端支持待办列表，才在客户端内部创建或恢复 `VERIFY-1`；无论客户端是否支持，都不得在聊天正文展示 VERIFY 清单。
3. 读取 `../../cli.md`，保存当前任务工作区绝对路径。截图/Markdown 分支同时读取 `../../references/pasted-reference-input-example.md`，但确认前不写正式文件。
4. 不扫描环境变量、旧 Skill、下载目录或 license 文件寻找替代凭据。Consent 已确认后若业务命令返回 `AUTH_SESSION_REQUIRED`，先执行一次 `./if-libclaw auth status`；只有明确输出 `Not logged in.` 才按 `verification-auth` 的单次登录流程暂停。浏览器授权完成后只恢复当前 Stage，不重发三项披露，也不跳过已获得的 Consent。
5. 确认后在内部完成 `VERIFY-1`。如客户端随后需要结构化问题，只能在完整披露已经可见且不再用于获取首次 Consent 的前提下使用；首次 Consent 一律使用上面的纯文本“继续/取消”。截图/Markdown 的确认必须同时指向刚展示的结构化字段和外部影响；只说“帮我查一下”不算确认。

若当前消息已明确表示“确认、继续或直接执行”，并明确指向本次文件及上述文件处理、来源查询和计费影响，可作为当前确认。包含“尚未确认、等待确认、确认后再执行”等否定或条件含义时一律不算确认。

## 完成条件

- 文档文件信息已核对，或截图/Markdown 的结构化字段已完整展示；
- 三项影响已披露；
- 披露/提问之后有新的明确授权事件，或当前消息本身满足完整授权条件。

## 禁止事项

- 确认前不执行 `reference-context`、不上传论文、不查询来源。
- 截图/Markdown 确认前不写入正式 JSON；不得把预览、TODO 或 Agent 自述当成用户确认。
- 不读取 `.env`、Shell 历史、Keychain、Agent 记忆或其他凭据文件寻找替代 Key；也不要求用户运行终端命令来写入 Key。
- 授权、权限、版本、计费、配给或文件识别服务 HTTP 401/403/422/503 错误不得触发 `login`；保持当前 Stage 并简短报告，不换 Key、URL、Header、flag 或认证方式。

## 下一 Stage

确认后读取 `../verification-context/STAGE.md`；取消则停止。
